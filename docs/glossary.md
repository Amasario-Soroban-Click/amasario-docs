# Glossary

Words that appear in more than one repository and mean something specific here. Where a
term has a normative definition, the specification is the authority and this page only says
which word to look up; where it is a convention of the tooling, this page is the definition.

## The two that cause the most confusion

**Observation** — a fact the engine obtained from a source it can name: a contract's bytes, a
recorded digest, a transaction the endpoint returned. An observation carries where it came
from.

**Inference** — a conclusion the engine drew from observations, by a rule it applies the same
way every time. An inference is not weaker than an observation; it is a different kind of
claim, and a document that does not distinguish the two is unreadable for the purpose it
exists.

Closely related, and the reason the project exists:

**Refusal** — the engine declining to answer, and saying so. A refusal is a result. The rule
the whole design serves is that a failure must never become an empty result, because "no
dependencies were found" and "no search for dependencies was performed" are the same JSON in
almost every tool that does this, and they are not the same fact.

**Basis** — the recorded reason a claim is made: which observation, which rule, which
boundary. A claim without a basis is an assertion.

## Identity

**Artifact identity** — what a built thing is: name, version, digest, build metadata. The
normative definition is the specification's.

**Executable identity** — what was actually deployed and is actually running. Distinct from
artifact identity, and the distinction is the entire point of provenance: a build whose
digest matches is evidence about the build, not about the chain.

**Digest** — a hash of exact bytes. It is a contract here rather than a fingerprint: the
reference contract's digests are committed, CI rebuilds and compares, and the explorer
re-hashes every vendored document. A digest is only meaningful if the bytes behind it are
reproducible.

## Boundaries

**Observation boundary** — the stated limit of what a run could see. A public endpoint, a
refused connection, a depth cap, an input file that was handed over rather than fetched. It
is recorded in the document, not only in a log.

**Bounded search** — a traversal given an explicit limit. When it stops early it reports
**truncation**, so a short result is never mistaken for a complete one.

**Vendored document** — a file the explorer copies verbatim from the engine, at a recorded
commit, with its digest recorded in a manifest and re-checked in CI. Vendored is not
generated: a vendored file is evidence, and a generated one is a rendering.

## Verification

**Status** — one of five, and they are not degrees of one scale. `VERIFIED`,
`PARTIALLY_VERIFIED`, `UNVERIFIED`, `CONFLICTING`, `UNKNOWN`. Two of them mean opposite
things: `UNVERIFIED` is "nothing was obtained to check against" and `CONFLICTING` is "the
evidence refutes the claim". Collapsing them would make a refusal read as a finding.

**Confidence** — how strong the evidence is. Independent of status: a claim can be
`VERIFIED` at low confidence (thin evidence that is nonetheless consistent) and `UNVERIFIED`
at unknown confidence (nothing obtained). Status says *whether* the evidence supports the
claim; confidence says *how much* evidence there was.

**Vector** — a fixed input with a canonical expected output, published by the specification.
Reproducing a vector byte for byte is how the engine demonstrates conformance, and adding one
is required of any normative change.

**Fixture** and **corpus** — a fixture is one committed input; the corpus is the collection of
them, generated deterministically and regenerated by the engine's own tooling. CI checks that
the corpus the engine generates from the fixtures is the corpus that is committed, so the
two cannot drift.

**Reference contract** — a small Soroban contract pair built from source in this organisation
purely to be analysed: a caller and a callee, whose compiled bytes are committed as fixtures
with recorded digests. It is not deployed, and its purpose is to give the dependency and
provenance code a real, reproducible input rather than a synthetic one.

## Versions

**Specification version** — what a document means. Normative, and the authority on meaning.

**Engine version** — the implementation. It carries `SUPPORTED_SPEC_VERSION` and refuses a
document from a newer minor version rather than guessing at a field it does not implement.

**API version** — the envelope around a document (`amasario.dev/v1`), so a stored document
remains interpretable after both numbers above have moved.

**Deterministic** — identical inputs produce identical bytes, across runs and across
machines. It is a tested property here, not an aspiration, and a machine-specific absolute
path baked into a build once broke it.
